# jmaxml-php

気象庁防災情報XMLの **非公式** PHP ライブラリ群です。気象庁とは関係ありません。

An **unofficial** set of PHP libraries for JMA (Japan Meteorological Agency) disaster information XML. Not affiliated with JMA.

## パッケージ

| パッケージ | 内容 | Packagist |
|---|---|---|
| [`jmaxml/core`](packages/core) | 電文を公式 XML スキーマから生成した型付きオブジェクトとして読む | [jmaxml/core](https://packagist.org/packages/jmaxml/core) |
| [`jmaxml/codes`](packages/codes) | 地震関係のコード表（都道府県・細分区域・市町村・震度観測点・震央地名・津波予報区）を引く | [jmaxml/codes](https://packagist.org/packages/jmaxml/codes) |
| [`jmaxml/feed`](packages/feed) | 公開 Atom フィードをポーリングし、新着の電文を絞り込んで返す（抜けの検知つき） | [jmaxml/feed](https://packagist.org/packages/jmaxml/feed) |
| [`jmaxml/earthquake`](packages/earthquake) | 地震の電文を地震イベントにまとめ、登録した市町村が震度いくつ以上だったか、取り消されたかを判定する | [jmaxml/earthquake](https://packagist.org/packages/jmaxml/earthquake) |

使い方は各パッケージの README を参照してください。

## 開発

```bash
composer install
composer test       # PHPUnit（実サーバーに接続するテストは除外。vendor/bin/phpunit --group live で実行）
composer analyse    # Psalm
composer lint       # Pint
composer generate   # resources/jmaxml から packages/core/src の型と packages/codes/src/Data のコード表を再生成
```

`packages/core/src` と `packages/codes/src/Data` のうち、先頭に `This file is generated by tools/codegen` とあるファイルは生成コードです。手で編集せず、`tools/codegen` を直して `composer generate` を実行してください。

## リリース

4 つのパッケージは、いつも同じ版番号でまとめて公開します。各パッケージは `shimomo/jmaxml-php-<package>` に分割され、Packagist にはその分割先を登録しています。

main には PR からしか入れられない（ルールセットで直接の push を止めている）ので、リリースは 2 段階で行います。どちらの段階も main には push しません。

```bash
bin/release.sh prepare 0.1.2   # 版を上げる PR を作る
# PR の CI が通ったら squash マージする
git pull
bin/release.sh publish 0.1.2   # main にタグを打ち、各パッケージを公開する
```

`prepare` は次のことを順に行います。

1. 事前確認（下の「止まる条件」）
2. `release/<version>` ブランチを作る
3. `CHANGELOG.md` の「Unreleased」の下に版の見出しを入れる（「Unreleased」の見出しは残る）
4. `packages/*/composer.json` の相互依存（`^<version>`）と branch-alias を更新し、ルートの `composer.json` に反映する
5. 3 と 4 を `chore: prepare release <version>` としてコミットし、ブランチを push して PR を作る（本文に今回の版の CHANGELOG が入る）
6. main に戻る

`publish` は次のことを順に行います。

1. 事前確認（下の「止まる条件」）
2. 公開する版、直前の版、コミット、パッケージを出して確認を求める。`y` と答えたときだけ先に進む（`n` と答えれば、事前確認だけを試せる）
3. 版の節を足したコミット（prepare の PR をマージしたコミット）に署名付きのタグを打って push する。その後に main に入ったコミットはタグに入らず、次の版に回る
4. 各パッケージをタグの時点で `git subtree split` し、分割先に push して、タグと GitHub Release を作る

- **前提**：分割先の 4 リポジトリがあること、`gh` にログインしていること、`jq` と `composer` があること、コミットとタグに署名できる GPG（パスフレーズはキャッシュしておく）
- **版番号**：コード表の更新だけならパッチ版（`0.1.1`）、公開 API が変わるときはマイナー版（`0.2.0`）を上げます
- **CHANGELOG**：「Unreleased」に手書きの項目があれば、それをそのまま今回の版の項目にします。無ければ、直前のタグ以降のコミットの件名を使います。版の節は版を上げるコミットに入るので、タグの時点の `CHANGELOG.md` にその版の節が載ります
- **prepare の PR をマージするまで、ほかの PR をマージしない**：マージすると、その変更はタグに入るのに、今回の版の CHANGELOG には載りません
- **止まる条件**：どちらの段階でも、版番号の形が違う、直前のタグより新しくない、main にいない、未コミットの変更がある、同じタグが手元か origin にある、手元の main が origin とずれている、分割先のリポジトリに届かない。`prepare` ではさらに、`CHANGELOG.md` にもうその版の節がある、`release/<version>` ブランチが手元か origin にある。`publish` ではさらに、`CHANGELOG.md` にその版の節が無い、相互依存が `^<version>` になっていない（どちらも、prepare の PR がまだマージされていないということ）。どれかに当たると、何も変えずに理由をすべて出して止まります

途中で失敗したときは、どこまで進んだかを確かめてから再開します。

- **prepare をやり直す**（PR を作る前に止まった、マージ前の PR を作り直したい）：main には何も入っていません。PR があれば閉じます。`git switch -f main` で main に戻り（書き換えた `CHANGELOG.md` と `composer.json` 群は捨てる）、`git branch -D release/<version>` で手元のブランチを、`git push origin --delete release/<version>` で origin のブランチを消してから、`bin/release.sh prepare` をやり直します
- **publish でタグがまだ origin に無い**（`git ls-remote --tags origin <version>` で見えない）：何も公開されていません。手元にだけタグがあれば `git tag -d <version>` で消してから、`bin/release.sh publish` をやり直します
- **publish でタグが origin にある**：公開は始まっています。まだ公開されていないパッケージについてだけ、下のコマンドを実行します。手元にタグが無ければ、先に `git fetch --tags` で取ってきます。分割はタグの時点で行うので、main がその後に進んでいてもかまいません（前回の失敗で残った一時タグと作業ブランチは、自動で消してからやり直します）

```bash
sh -c '. bin/lib/package-release.sh; package_release_publish 0.1.2 packages/feed'
```

## 出典

このリポジトリには、気象庁が公開している技術資料（XML スキーマ、辞書、サンプル電文、個別コード表）を `resources/jmaxml/` に同梱しています。`jmaxml/codes` のデータは、個別コード表を加工して作成したものです。

出典：[気象庁ホームページ](https://xml.kishou.go.jp/)
